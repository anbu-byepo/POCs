Real app, not a mockup -- tap Continue with Google, pick any Google account in the real consent popup, and see that channel's real videos come in. Screens below are built to match the connect/read design exactly. No backend -- everything happens in this browser tab. See ../audit/youtube-feasibility-plan.md.

Feasibility spike setup (not part of the design -- dev only)

Defaults to this project's own Client ID (hardcoded in app.js -- not a secret, unlike a client secret, so this is safe). Override here only to test against a different Web application-type client; your override is saved to this browser's localStorage and takes priority from then on.

Whichever client ID is active, its Authorized JavaScript origins must list every origin this app is actually opened from -- http://localhost:8000 (and/or http://127.0.0.1:8000) for local dev, and the exact deployed origin (e.g. https://your-site.netlify.app, no trailing slash or path) for a live URL. Missing one means Google rejects the popup with origin_mismatch. Its OAuth consent screen must also list .../auth/youtube.readonly, .../auth/youtube.upload and .../auth/userinfo.email as scopes (Testing status is fine as long as your account is added as a test user).
